# slex skill｜创始人短视频纯口播写作

## 核心原则

写得像同一个创始人在真实生活里继续说话，但不能像他过去任何一条文案的换词版。

只写不依赖画面的纯口播。保留临场感、自嘲、利益冲突和不完美感；事实、数字和事件性质必须来自用户素材，不得为了点击虚构。

## 开始前必须读取

每次创作先读取：

- `references/style-dna.md`：风格 DNA 与语言边界。
- `references/modes.md`：六种口播模式和选型方法。
- `references/angles.md`：角度生成与差异判定。
- `references/guardrails.md`：禁用项、事实边界和去重规则。
- `references/io-and-scoring.md`：输入补全、输出规范和评分表。

涉及该 AI 编程平台时，再读取 `references/product-context.md`。用户提供的新事实优先于背景文件。

## 工作流

1. 提取事实：人物、事件、数字、时间、利益、风险、未解决问题。
2. 判断目的：涨粉、引流、立人设、表达观点、推进连续剧情或征求意见。
3. 选择一个主模式。最多用一个辅模式，不得六种结构混写。
4. 先生成不少于 12 个一句话角度；按 `angles.md` 筛选。
5. 需要多条时，让每条至少改变两个核心变量：叙事主体、利益关系、冲突对象、用户痛点、时间节点、核心判断。
6. 为每个入选角度生成 3 个开头，只保留最强的一个。
7. 写 300—500 字正文；用户指定长度时服从用户。
8. 按评分表和硬性规则自检。不合格先重写，再交付。

## 写作约束

- 开头直接进入事件、选择、利益或反常识判断，不铺行业背景。
- 一条只讲一个核心矛盾；旧背景最多选两个核心资产展开。
- 产品通过冲突、用户利益或真实行为自然出现，不完整背诵卖点。
- 每 3—5 句加入新信息、反转、数字、人物动作或利益变化。
- 用短句、大白话和自然停顿；允许少量重复，但必须推动情绪。
- 每篇至少有一处真实的自我暴露：犹豫、难堪、兴奋、自我质疑、承认算错或一句不完全工整的临场反应。不要把它加工成金句。
- “兄弟们”、脏话、投资人、贷款、套壳不是必选词，更不是风格本身。
- 单独听音频必须完整理解。禁止“大家看这里”“点一下”“看到没有”等画面指令。
- 标题若未被要求，不主动生成。若被要求，标题必须被正文事实支撑。

## 默认交付

先给方向名和一句话切入，再给可直接拍摄的完整口播。用户要求“纯成片模式”时，只输出正文。

多条文案之间不得共享同一开头骨架、同一故事壳或同一结论。不要展示内部打分过程，除非用户要求审稿依据。

## 不适用

- 产品录屏解说、操作步骤、分镜、剪辑点。
- 短视频标题专项、直播话术、图文、小红书、剧情短片。
- 新闻事实核查。遇到未经用户确认的最新事实，先核实或明确作为假设。

## 常见失败

| 失败 | 修正 |
|---|---|
| 像商业说明书 | 加入正在发生的人物动作、真实压力和不完美反应 |
| 逻辑正确但不像本人 | 打散过度工整的三段论，补一处自我暴露和一处自然口语回摆 |
| 每条都被骂、融资、贷款 | 保留冲突逻辑，换叙事主体和利益关系 |
| 把“口语”写成满篇脏话 | 用自嘲、停顿、反问和具体数字制造活人感 |
| 产品卖点背一遍 | 只保留与本条矛盾直接相关的一个卖点 |
| 三条只是换开头 | 检查是否至少改变两个核心变量 |
| 标题升级事实 | 区分接触、意向、投资、控股、收购和已经完成 |

## 迭代

用户给出新样本或否定反馈时，不要立刻重写全部规则。先标记：

1. 新增稳定规律；
2. 对现有规则的修正；
3. 只适用于单篇的偶然表达；
4. 新增高频词或故事壳。

稳定出现于多个样本且跨题材成立的规律，才更新参考文件。
